> **一句话定位：** 安装浏览器扩展后，打开任意哔哩哔哩用户主页，一键分析其公开内容与互动数据，生成可解释、会随时间变化的兴趣画像。**无需服务器、无需账号、无需 API Key、无需配置本地 AI。**
<callout icon="🎯" color="blue_bg">

## 一、项目暂定名：B站兴趣画像
**推荐名称：B站兴趣画像**
理由：
- 「B站」直接说明平台；
- 「兴趣」直接说明分析对象；
- 「画像」直接说明最终输出；
- 普通用户不需要理解 AI、图谱、Analyzer 等技术概念；
- 与已发现的「Bilibili-UserComponentTag / 用户成分标签」等竞品命名方向不同；
- 搜索和传播时语义清晰。
**可考虑的备选：**
- B站兴趣分析
- B站兴趣图谱
- B站兴趣雷达
- B站公开兴趣画像
当前优先使用 **「B站兴趣画像」**。正式发布前再做一次 GitHub、GreasyFork、Chrome/Edge 扩展商店的同名检索。
## 二、目标用户
面向中国普通 B 站用户，而不是开发者工具用户。
典型使用场景：
- 看看「B站眼中的自己」；
- 分析自己的长期兴趣变化；
- 在访问公开用户主页时了解对方主要关注什么内容；
- 生成可分享的「我的 B 站兴趣画像」；
- 对某个兴趣领域查看更细的兴趣组成。
## 三、核心产品体验
用户不需要理解任何技术细节。
1. 安装浏览器扩展。
2. 正常访问哔哩哔哩。
3. 打开自己或其他用户的主页。
4. 点击「分析兴趣」。
5. 扩展读取当前用户可正常访问的公开信息。
6. 在浏览器本地完成分析。
7. 数秒后展示兴趣画像、兴趣层级、置信度、时间变化与判断依据。
示例结果：
```plain text

├─ 二次元游戏      76%
│  ├─ 原神         68%
│  ├─ 崩坏：星穹铁道 51%
│  └─ 明日方舟     29%
├─ FPS            42%
└─ 独立游戏        24%

科技              73%
├─ AI             66%
│  ├─ Agent       47%
│  └─ 大语言模型   43%
├─ 编程           53%
│  ├─ Python      38%
│  └─ C++         27%

```
## 四、不是固定标签检测器
项目不能局限于「二游浓度」或预先写死几十种兴趣。
目标是：
**公开行为 → 内容理解 → 兴趣发现 → 层级归类 → 强度评分 → 时间变化 → 可解释证据**
系统应该能够发现长尾兴趣。例如：
- 苏联建筑
- 机械键盘
- 东方 Project
- 铁路
- 摄影器材
- 大语言模型
- 古典音乐
- 赛车
- 某一具体游戏、动漫或 UP 主生态
即使开发者没有提前为这个兴趣专门编写规则，也应尽量识别出来。
## 五、公开数据来源
只处理用户正常访问时能够看到的公开信息，例如：
- 公开投稿/作品；
- 公开动态；
- 公开收藏；
- 公开评论；
- 可合理关联的公开弹幕；
- 视频标题、分区、标签、UP 主及主题信息；
- 其他明确公开且适合分析的内容。
不同数据源具有不同证据权重。
例如：
- 主动投稿：高权重；
- 长期收藏：较高权重；
- 持续评论：中高权重；
- 普通评论：中等权重；
- 单次弹幕：较低权重。
不能因为一次偶然互动就断定用户具有某项兴趣。
## 六、兴趣评分模型
基础思想：
`兴趣得分 = 行为权重 × 内容相关度 × 时间衰减 × 重复证据修正`
需要考虑：
- 行为类型；
- 内容与兴趣的语义相关程度；
- 发生时间；
- 同一兴趣是否长期重复出现；
- 是否来自多个独立数据来源；
- 样本数量；
- 数据缺失情况。
最终同时输出 **兴趣强度 + 置信度**，避免制造虚假的精确感。
## 七、时间维度
兴趣不是静态标签。
项目应能够表示：
- 当前主要兴趣；
- 兴趣持续时间；
- 最近明显增强的兴趣；
- 正在减弱的兴趣；
- 不同年份/月份的兴趣变化。
例如：
```plain text
2024  动漫 ████████
      游戏 ██████
      AI   ██

2025  动漫 ██████
      游戏 ███████
      AI   █████

2026  动漫 ████
      游戏 ███████
      AI   █████████
```
这可以成为项目区别于普通「成分检测」脚本的重要功能。
## 八、可解释性
任何主要结论都应该允许用户点击「为什么」。
例如：
**AI / 大模型兴趣：86%，置信度高**
依据：
- 相关公开收藏 24 项；
- 相关公开评论 17 条；
- 最近 6 个月持续出现；
- 内容集中于 Agent、LLM 编程、本地部署；
- 多个独立数据来源相互印证。
原则：**AI/算法不能只给结论，还要给证据。**
## 九、技术架构
```plain text
浏览器扩展
    ↓
公开数据采集层
    ↓
数据清洗 / 标准化
    ↓
实体与主题识别
    ↓
本地兴趣分析引擎
    ├─ 规则
    ├─ B站元数据
    ├─ 关键词 / 实体库
    ├─ 轻量语义模型
    └─ 聚类 / 兴趣发现
    ↓
兴趣层级图谱
    ↓
权重 + 时间衰减 + 置信度
    ↓
可视化 UI
```
### 本地 AI 的定义
用户**不需要配置本地 AI**。
如后续确实需要更强语义能力，可以将小型 ONNX/WASM/WebGPU 模型作为扩展内部组件自动运行。对普通用户而言仍然是零配置。
### 可选高级 AI
未来可以允许高级用户自行接入云端模型 API，但必须是可选功能。
基础功能必须始终满足：
**No Server · No Account · No API Key · No Local AI Setup**
## 十、隐私与产品边界
核心原则：**本地优先，只分析公开内容。**
默认：
- 不建立服务器端用户画像数据库；
- 不上传被分析用户的数据；
- 不要求注册账号；
- 分析结果保存在本地；
- 明确显示数据来源与样本数量。
只描述能够从公开内容支持的 **兴趣和线上内容表达/互动特征**。
不要尝试推断：
- 现实人格定性；
- 医疗或精神健康状态；
- 性取向等敏感个人属性；
- 其他缺乏公开证据、容易造成伤害的私人属性。
「行事风格」建议在产品中称为 **公开表达特征 / 互动风格**。
## 十一、与现有竞品的差异
已经发现的竞品主要集中在：
- 用户成分标签；
- 浏览记录分析；
- 评论词云/舆情分析；
- B站数据抓取工具。
本项目不应该成为另一个「关键词 → 成分标签」脚本。
核心差异化组合：
**所有兴趣自动发现 + 层级兴趣图谱 + 多来源交叉验证 + 时间演化 + 置信度 + 可解释证据 + 完全本地 + 普通用户零配置。**
## 十二、传播功能
重点设计 **「B站眼中的我」**。
允许用户一键生成适合分享的兴趣画像卡片，例如：
```plain text
我的 B 站兴趣画像

AI / 大模型       86%
游戏              73%
动漫              61%
编程              58%
音乐              37%

今年变化最大：
AI ↑↑
编程 ↑
动漫 ↓

我的隐藏兴趣：
机械键盘 · 铁路 · 科幻
```
分享图片不包含敏感信息，用户主动选择是否生成。
这可能成为项目自然传播的重要入口。
## 十三、扩展性
长期可以提供 Analyzer API，但不让普通用户感知复杂度。
第三方开发者可以开发：
- 游戏兴趣增强分析；
- ACG 兴趣分析；
- 音乐兴趣分析；
- 科技兴趣分析；
- UP 主生态分析；
- 自定义领域兴趣分析。
核心负责数据标准化、评分、时间模型、置信度、UI 和插件接口。
## 十四、版本路线
### v0.1 — 能分析
- 浏览器扩展基础框架；
- 用户主页一键分析；
- 获取少量稳定的公开数据源；
- 基础兴趣分类；
- Top 兴趣展示；
- 完全本地运行。
### v0.2 — 分析得像样
- 多数据源；
- 行为权重；
- 时间衰减；
- 置信度；
- 判断依据页面；
- 更细的兴趣层级。
### v0.3 — 从标签升级到兴趣发现
- 长尾兴趣发现；
- 实体识别；
- 轻量语义能力；
- 自动构建兴趣树；
- 减少固定词库依赖。
### v0.5 — 有传播能力
- 「B站眼中的我」；
- 分享卡片；
- 兴趣时间线；
- 年度/阶段兴趣变化；
- UI 打磨。
### v1.0 — 完整产品
- 稳定的数据适配；
- 完整兴趣图谱；
- 高质量可解释系统；
- 本地隐私控制；
- Analyzer 扩展接口；
- Chrome / Edge 等主流浏览器友好安装；
- 完整 README、文档和开源发布流程。
## 十五、成功标准
这个项目是否成功，不以「用了多先进的 AI」衡量，而以：
> **一个完全不懂编程的 B 站用户，能不能安装以后点一下，就得到一份觉得“有点准、看得懂、愿意分享”的兴趣画像。**
技术复杂度应该由项目承担，而不是转嫁给用户。
