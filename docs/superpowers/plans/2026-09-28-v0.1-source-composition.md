# v0.1 来源组合 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** 已获用户批准并获明确执行授权；2026-09-29 Phase 0 closure audit 与 Global Gate 最终处置已获批准，Phase 1 可按本计划开始。分页与 SPA 子项保留延期风险及重验条件。

**Goal:** 在获准的浏览器扩展中实现 v0.1 来源组合：公开动态提供兴趣证据，公开基础资料只提供身份与上下文。

**Architecture:** 内容脚本只读取当前空间页已渲染的公开 DOM。基础资料产出独立的 `ProfileContext`；动态经身份与内容边界验证后才产出 `EvidenceItem`。Pipeline 仅将动态 EvidenceItem 交给后续分析层，并把拒绝原因保留为来源状态或 warning。

**Tech Stack:** TypeScript strict、WXT、React、Zod、Vitest、Playwright、pnpm；初始持久化采用项目既定的 IndexedDB/Dexie 路线，但本计划不增加持久化功能。

**Spec:** `docs/superpowers/specs/2026-09-28-v0.1-source-composition-design.md`

## Global Constraints

下列 DOM-only、Contract 和构建细节是本已批准计划的实施提案，不新增 Phase 0 Gate；只有执行前置条件满足后才可落实。

- 执行前必须确认已授权的 Phase 0 closure audit 已完成，且用户已明确批准当时的 Global Gate 处置、进入 Phase 1 和执行本计划；已批准的 deferred validation / residual risk 本身不构成通过。
- 仅支持 Chrome / Edge Chromium 与 Manifest V3；只读取 `https://space.bilibili.com/*` 当前已渲染的公开 DOM。
- 不发起 B站 API 请求，不读取 Cookie、Token 或页面私有 JS state，不绕过登录、CAPTCHA、权限或风控。
- 公开动态是唯一兴趣行为证据源，且当前只在已验证的正常已登录公开动态页范围内产出证据；公开基础资料只产生 `ProfileContext`。
- 投稿与收藏不注册、不采集、不进入 `EvidenceItem` 或兴趣推断。
- 身份、结构、正文或页面状态无法确认时不产生兴趣 EvidenceItem；unknown、unavailable、partial 和 empty 不得互相替代。零张卡片本身不证明 empty；无已批准且有效的稳定性 proof 时，单次空态快照返回 unknown/null。
- 原始 B站字段只存在于 Source 与 Normalizer 边界；Analyzer 不得访问 DOM、网络、Cookie、数据库或 Raw。
- 所有测试使用脱敏 fixture；不得将真实 UID、昵称、正文、视频 ID 或会话信息写入仓库。

## Review Focus

- 卡片作者显示名、空间头部或路由身份不一致时，卡片不得进入 EvidenceItem。
- 转发引用、通用“分享动态”文案和合作占位不得作为当前用户兴趣正文。
- 隐藏空态节点与零个已渲染动态卡片必须区分；不明状态返回 unknown/unavailable。
- 动态没有精确时间或单条链接时，保留 `timestamp=null` 与页面级追溯，不能补造值。
- 基础资料、投稿和收藏均不得被后续 Pipeline 当作兴趣 EvidenceItem。

### Task 2: 定义来源与证据 Contract

**Files:**
- Create: `src/core/contracts/source.ts`, `src/core/contracts/source.schema.ts`
- Create: `tests/unit/source-contract.test.ts`

**Interfaces:**
- Produces: `ProfileContext`, `EvidenceItem`, `SourceStatus`, `SourceWarning` 和 `SourceResult<T>`。
- Rule: `EvidenceItem['source']` 只允许 `dynamic`；`ProfileContext` 不能转换为 `EvidenceItem`。

```ts
export type SourceStatus = 'available' | 'partial' | 'empty' | 'unavailable' | 'unknown'

export interface ProfileContext {
  userId: string
  displayName: string
  description: string | null
  sourceUrl: string
}

export interface EvidenceItem {
  source: 'dynamic'
  userId: string
  title: string | null
  text: string
  timestamp: string | null
  sourceUrl: string
  traceGranularity: 'page' | 'item'
}

export interface SourceWarning {
  code: 'identity_mismatch' | 'content_unusable' | 'page_state_uncertain'
  message: string
}

export interface SourceResult<T> {
  status: SourceStatus
  data: T | null
  warnings: SourceWarning[]
}
```

`available`/`partial` 必须携带经确认的数据；`empty` 仅用于符合 Spec 且附有有效稳定性 proof 的空态，集合数据为 `[]`；`unknown`/`unavailable` 的数据为 `null`。当前计划没有 proof producer，因此单次空态候选为 `unknown/null`；单卡拒绝不等于页面空态。

- [ ] **Step 1: 写失败的 Contract 测试**

覆盖有效动态证据、profile context、缺精确时间/链接、非法 `profile` EvidenceItem，以及 unknown/unavailable 不携带兴趣证据；保留 `SourceResult` 中 `empty` + `[]` 的 schema/结构校验，但不测试稳定性 proof 或状态升级。另覆盖身份和正文已确认、但单条链接或精确时间缺失时允许 `partial` EvidenceItem。
